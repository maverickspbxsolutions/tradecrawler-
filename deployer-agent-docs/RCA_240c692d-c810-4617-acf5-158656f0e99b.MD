# RCA — TradeCrawler (signal-engine-158): Cloudflare "unparseable/empty origin response" on login

## Summary
The reported Cloudflare error ("origin returned an empty response / malformed HTTP headers / invalid response") was a **transient window during the rolling redeploy**, not an ongoing origin failure, a code bug, or a missing secret. The production backend is currently **up and serving**, and the login endpoint returns **200 at the origin**.

## Deployment context
- Deployment: `signal-engine-158` (custom domains: `tradecrawler.live`, `www.tradecrawler.live`, both verified)
- Live URL: https://signal-engine-158.emergent.host
- Active run: `240c692d-c810-4617-acf5-158656f0e99b` (redeploy), status **success**, promoted **2026-10-03T22:28:28Z**
- Template: `fastapi_react_mongo_shadcn_base_image` (farm), frontend_type: cloudflare, tier_0, arm64
- A cluster of redeploys ran between ~20:46 and 22:28 — matching "a deployment was initiated shortly before this report."

## Evidence
1. **Origin health (live):** `GET /api/` → 200, body `{"service":"Crypto Signal Terminal","status":"ok"}`, ~476ms.
2. **Login works at origin (live):** pod logs show `POST /api/auth/login HTTP/1.1" 200 OK`, followed by many authenticated `/api/*` 200s (overview, signals, strategies, settings, market/*).
3. **Pods healthy:** both replicas (`...-52qdh`, `...-hsqz6`) `Running`, `ready:true`, `restart_count:0`. No OOMKilled, no CrashLoopBackOff, no image-pull errors.
4. **The only unhealthy signal was transient and boot-time:** `Startup probe failed: HTTP probe failed with statuscode: 503` at 22:27:52–22:28:53 (while the new pods' backend was still starting). It did not recur after the pods became ready.
5. **Secrets parity confirmed** (active run, names + non-empty state): ADMIN_USERNAME, ADMIN_PASSWORD, MONGO_URL, DB_NAME, JWT_SECRET, RESEND_API_KEY, RESEND_FROM_EMAIL, EMAIL_FROM_NAME, DERIV_APP_ID, DERIV_API_TOKEN, DERIV_OAUTH_APP_ID, CORS_ORIGINS, REACT_APP_BACKEND_URL, INTEGRATION_PROXY_URL, ENABLE_HEALTH_CHECK, WDS_SOCKET_PORT — all present, none empty. Every var the app requires in production is set.

## Root cause
During the rolling redeploy, the new backend pods briefly failed their Kubernetes startup probe with HTTP 503 while FastAPI/uvicorn was still booting (nginx up on :8080, backend on :8001 not yet accepting — the farm nginx `/health` returns 503 via `@health_error` until the backend answers). In that short boot window the origin returned 503/empty responses to Cloudflare, which Cloudflare rendered to the browser as the "empty/unparseable origin response" message. Once the pods passed the startup probe and were marked ready, traffic was served normally. The run promoted at 22:28:28 and the origin has returned 200s (including the login POST) since.

Note on the `GET /health 404` lines in the logs: that is the backend having no `/health` route; the farm template treats a 4xx from the backend as **healthy** (backend is responding). It is not related to the incident.

## Addressing the user's specific suspects
1. Backend pod up / not crash-looping — **UP**, both replicas ready, 0 restarts. The 503s were startup-only and have cleared.
2. Secrets/env parity — **full parity**, all required vars present and non-empty (list above).
3. DB binding — MONGO_URL present and non-empty; startup seeding succeeded (admin login returns 200, and authenticated endpoints serve data), so Mongo is reachable from the production pod.
4. Routing — `/api/*` correctly reaches the backend on :8001 (200s across all `/api/*` routes, including `POST /api/auth/login`). No 502/520 at the origin currently.

## Resolution / remaining action
No fix is required on the deployment side — the origin self-recovered when the rollout finished. The user should **retry login now** (hard-refresh or incognito to drop any stale edge/browser cache from the deploy window). If the Cloudflare error reappears **outside a deploy window** (i.e. while no redeploy is running), capture the failing request (timestamp + response headers via DevTools) and re-open — that would point to a different, reproducible edge/origin issue; nothing in the current evidence indicates one.
