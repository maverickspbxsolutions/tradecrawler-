# RCA — Production Resend email delivery (TradeCrawler / signal-engine-158)

## Request
Read-only audit of production secrets to determine whether live trade-alert email via Resend will work after the current deploy.

## Findings (from `list_secrets`, active run `d6fe5f95-7571-4c26-b7fb-ee2390ec821b`)
Secret values are KMS-sealed and never returned; metadata_available=true, so presence/empty/match checks are reliable.

1. **RESEND_FROM_EMAIL** — PRESENT, non-empty, **matches_expected=false** → its stored value does **NOT** equal `alerts@tradecrawler.live`.
2. **RESEND_API_KEY** — PRESENT, non-empty.
3. **EMAIL_FROM_NAME** — PRESENT, non-empty.

## Conclusion
Production email will **NOT** work as intended after the current deploy. `RESEND_FROM_EMAIL` exists in production but holds a value other than the verified-domain sender `alerts@tradecrawler.live`. If that value is still the default `onboarding@resend.dev` (or any non-verified sender), Resend returns 403 for any recipient except the account owner — matching the reported production failure.

## Why a redeploy alone will not fix it
Pre-existing production secret values are **NOT overwritten** on redeploy. Setting the value in preview `.env` and redeploying will NOT change the already-present production value. The value must be edited directly.

## Remediation (user action, via UI)
Deployment Panel → **Secrets** tab → update `RESEND_FROM_EMAIL` to `alerts@tradecrawler.live` → Save → Redeploy. `RESEND_API_KEY` and `EMAIL_FROM_NAME` are already present and need no change.
